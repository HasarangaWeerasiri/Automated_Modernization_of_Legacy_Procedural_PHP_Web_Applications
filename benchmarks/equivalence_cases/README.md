# E1 input cases

`<app>.json` was generated by `python scripts/equivalence/run_e1.py skeleton`. It holds one entry per SQL site from the independent grep. Fill it in **by hand**, using the schema and the seed data, never C3 output.

- **`inputs`.** Each input is one value the legacy PHP reads. `superglobal` inputs (e.g. `$_GET['id']`) are strings. A `variable` input is a value the slice could not compute (a function parameter, an include, a query result); the `note` says why. An `array` input must be an object with the listed `keys`, e.g. `{"id": "3"}`.
- **`cases`.** Replace the `null`s in `normal` (values that exist in the seed), `empty_result` (values that match nothing) and `boundary` (`0`, a large id, an empty string where allowed).
  - A case that still contains a `null` is skipped, so delete the cases you don't want.
  - `hostile_*` and `type_mismatch` are pre-filled from `docs/E1_equivalence_plan.md` §3; review them.
- **Sites with `"cases": "not needed: ..."`.** These are INCONCLUSIVE by rule (C3 did not convert them); leave them as they are.
- **Regenerating.** Don't rerun `skeleton` with `--force` after you start editing.
- **Before the MySQL run.** Check your edits with `python scripts/equivalence/run_e1.py dry-run --out <temp dir>`. Every converted site should be READY.

`<app>.seed.sql` holds hand-written seed rows for the fixtures, which have no INSERTs in their schema.
