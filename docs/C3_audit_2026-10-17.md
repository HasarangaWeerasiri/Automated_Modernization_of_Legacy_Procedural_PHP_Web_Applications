# C3 Data Layer Migration — Audit, 17 October 2026

Project J26-SE-329, component C3, branch `database-migration`, HEAD `6e92711`. Prepared for PP1 (Monday 20 October), with the component freeze planned for Sunday 19 October.

## How this audit was done

- **Read-only.** No pipeline run, no regeneration, no S15 evaluation, no database command, no MySQL password. The only file written is this report.
- **Tests were not rerun.** The test suites write generated outputs and pytest temp folders, and some tests read the untracked `output/` folders. I could not prove in the time available that every effect stays outside the repository, so every test count below comes from saved logs.
- **Sources.** Numbers come from committed evidence: `evidence/`, `benchmarks/ground truth/`, `docs/C3_results_summary.md`, the code, and `git` metadata. Some numbers come from the out-of-repo run that `scripts/summarize_evidence.py` made on 2026-10-16 at HEAD `bd575ad`, in the system temp folder `c3_current_code_2fzzsas9`. Those are labelled **[temp run]**. They are reproducible, but they are not committed evidence. `git log bd575ad..HEAD -- components/c3_data_layer/src components/c3_data_layer/tools` is empty, so that run matches today's pipeline code.
- **UNCONFIRMED** marks a number the repository evidence does not support. **NOT MEASURED** marks a metric with no measurement at all.
- **Privacy.** No HMS SQL text, dump value, credential or input value is reproduced. Only counts and file:line labels are used, the same labels that already appear in committed evidence.
- **Earlier report.** `docs/C3_audit_report.md` (15 October, pre-development) was read as background. Its findings are cited only where I re-verified them; section 9 lists which are now superseded.

### 1.3 Does Clinic's result overstate generalization?

Yes, if it is presented as "22/22 converted" or "100%" without the split.
- **Hard-coded literals:** the 7 templates contain Clinic table names (`patients`, `doctors`, `appointments`), column names (`full_name`, `hourly_rate`), `$_GET` keys and the default `'1,2'`.
- **Gates:** they accept only the exact Clinic file text.
- **Other apps:** the same pattern classes do not convert anywhere else. For example, hard_crud stays at 2/5 converted [temp run], with 3 sites unresolved at recovery.

| Measure | With templates | Without templates (general rules only) |
|---|---|---|
| Converted / detected sites | 22/22 (100%) | **15/22 (68.2%)** |
| Recovered by general recovery / detected | 17/22 (77.3%) | 17/22 (77.3%) |
| Sites a reviewer must handle | 0 | 7 (Q011–Q014, Q016 unresolved at recovery; Q010, Q020 recovered but not convertible by general rules) |

- **"Without templates" is a code-reading result, not a run.** It follows from the dispatch: without the ID branches, Q011–Q014 and Q016 stay UNRESOLVED. Q010 hits the multi-table rejection at `query_converter.py:368-373` because `_is_supported_join_select` rejects subqueries (`:553-554`). Q020 is a multi-table UPDATE. A run with templates disabled has **not** been measured.
- **Clinic has no author-verified ground truth.** These are pipeline counts, not accuracy. Clinic also has `generated_code_text_calls_not_literal: 3` in its security report [temp run]: the Q012/Q013 f-string identifier calls, which are allowlist-guarded.

### 5.2 A. Recommended architecture

**A separate, read-only C3 dashboard**, not an extension of another component's frontend. No shared team frontend exists to extend, and C2's Next.js app is generated output, not a host application.

- **Data layer:** one generated file, `dashboard_data.json`, plus copies of a pinned run's artifacts. It would be produced later by a new mode of `scripts/summarize_evidence.py` (for example `--dashboard-json <path>`), reusing its sourcing table so that every figure carries `{value, numerator, denominator, file, field, stage, app}`. The script is **not** changed now.
- **Frontend:** a static single-page app (Vite + React + TypeScript), built to plain files and served locally. This keeps PP1 offline and server-free.
  - **If the team prefers one stack:** use Next.js with `output: "export"` (same versions as C2), still static.
  - **Charts:** one small library (e.g. Recharts), with separate charts per metric.
- **Rules:**
  - Components contain **no research numbers**; they render only `dashboard_data.json`.
  - Every figure shows numerator/denominator, app, stage label and evidence path.
  - Missing figures render "Not yet measured".
  - HMS SQL text and source code are never shipped. HMS rows show counts and file:line only.
- **Run Analysis (later):** a separate localhost-only bridge (FastAPI is already in `requirements.txt`). It would:
  - accept only allowlisted app IDs, never arbitrary paths;
  - write to a new temp folder;
  - never touch `output/` or the frozen handoff;
  - return the run folder for the dashboard to load.

  Not for PP1.
